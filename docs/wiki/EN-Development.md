## Project structure

Everything Home Assistant loads is in `custom_components/tariffy/`:

| File | Purpose |
|---|---|
| `__init__.py` | Sets up and unloads a contract, sets up the panel, cleans up notifications on deletion and remembers the deleted contract |
| `manifest.json` | Domain, version, dependencies (`after_dependencies`) and links |
| `const.py` | Constants: domain, platforms, categories, names of the settings fields |
| `config_flow.py` | Setup, editing (reconfigure) and options (next contract), depending on the category |
| `coordinator.py` | Calculation of all values, tariff switch, cancellation reminder, low-instalment warning |
| `sensor.py` | The sensors of a contract |
| `button.py` | The buttons "Switch now", "Confirm cancellation" and "Confirm low-instalment warning" |
| `panel.py` | Sidebar panel, data interface (WebSocket) and permission check |
| `backup.py` | Backup, restore and the 30 days for deleted contracts |
| `history.py` | Entering old terms by hand into the history |
| `autarkie.py` | Calculation of PV self-sufficiency in the forecast |
| `leasing.py` | Calculation for leasing (kilometres) |
| `loan.py` | Repayment plan for loans |
| `diagnostics.py` | Diagnostics download with redaction of personal data |
| `strings.json` | Texts of the form (English, basis of the translations) |
| `translations/de.json`, `translations/en.json` | German and English texts |
| `frontend/tariffy-panel.js` | Code of the panel |
| `frontend/tariffy-i18n.js` | Texts of the panel (German and English) |
| `frontend/tariffy-icons.js` | Icons of the panel |
| `frontend/tariffy-style.js` | Styles of the panel |
| `brand/icon.png` | Icon of the integration |
| `CHANGELOG.md`, `README.md` | Own versions for the integration; both changelogs are maintained (see [Releases and Beta](EN-Releases-and-Beta#rules-for-contributors)) |

More directories in the repository:

| Path | Content |
|---|---|
| `tests/` | All tests (`test_*.py`) and the panel preview in `tests/frontend/` |
| `docs/wiki/` | Sources of the wiki (these pages) and `docs/wiki/images/` with the images |
| `docs/beta-releases.md` | Description of the beta path |
| `scripts/check_wiki.py` | Check of the wiki pages |
| `.github/` | Workflows (`release.yml`, `validate.yml`), release scripts and the issue forms |
| `hacs.json`, `pytest.ini`, `requirements_test.txt`, `ruff.toml` | Settings for HACS, tests and lint |

The panel builds on the four files in `frontend/`; the code loads the other three with its own `?v=` version, because the static path is cached for a long time.

## Tests and lint

The tests use `pytest-homeassistant-custom-component`. `pytest.ini` sets `asyncio_mode = auto`, `testpaths = tests` and `pythonpath = .`. CI uses Python 3.13.

```bash
pip install -r requirements_test.txt
pytest
```

Lint with Ruff, as in CI (correctness rules `E9` and `F` only, target `py312`):

```bash
ruff check custom_components
```

The release scripts have tests of their own:

```bash
.github/scripts/test-release-notes.sh
.github/scripts/test-release-plan.sh
```

A single test, for example for the issue forms:

```bash
pytest tests/test_issue_templates.py
```

> **Good to know:** Run the full suite and Ruff before every push. CI (`validate.yml`) also checks HACS and Hassfest.

## Panel preview

The directory `tests/frontend/` holds sample data and a preview of the panel:

- `fixtures.json`: What `tariffy/contracts` returns for six realistic contracts, generated by the **real backend**. `tests/test_panel_fixtures.py` fails when the file is out of date.
- `preview.html`: Loads the panel with a mock `hass`.

Regenerate:

```bash
UPDATE_FIXTURES=1 pytest tests/test_panel_fixtures.py
```

Open the preview: start a web server in the root of the repository and open the page.

```bash
python -m http.server
```

Then open `/tests/frontend/preview.html?lang=de` in the browser. Parameters: `lang=de|en`, `state=loading|empty|error`, `narrow=1` and `theme=light|dark`.

## Regenerate screenshots

Two scripts render the preview in headless Chromium with the date fixed to 2026-07-12 and write screenshots:

- `tests/frontend/screenshots.mjs`: all screenshots in the dark design
- `tests/frontend/screenshots-light.mjs`: the main screenshots (German desktop and phone, English at 960 px, all five tabs) in the light design, written as `*-light.png` next to the dark ones

```bash
node tests/frontend/screenshots.mjs [output folder]
node tests/frontend/screenshots-light.mjs [output folder]
```

Both need Playwright with a Chromium browser and are **not part of CI**. Without an output folder `screenshots.mjs` writes to `docs/panel-preview/`; for the wiki pass `docs/wiki/images`. For images with a light variant the wiki uses a `<picture>` element that shows the light or dark file by the visitor's colour scheme.

## Check the documentation

```bash
python3 scripts/check_wiki.py
```

The script checks the pages in `docs/wiki/`: links and anchors, images (file exists, at most 500 KB), Mermaid blocks and whether every German page has its English page with the same structure. On a problem it ends with exit code 1. In addition `tests/test_docs.py` checks in the test suite that the documentation does not point to things that do not exist.

## Publish the wiki

The GitHub wiki is a repository of its own (`weskona/tariffy.wiki`). The sources are in `docs/wiki/` and are copied into it:

1. Clone the wiki repository: `git clone https://github.com/weskona/tariffy.wiki.git`
2. Copy all `*.md` files from `docs/wiki/` into it.
3. Copy the folder `docs/wiki/images/` into it as `images/`.
4. Commit and push.

```bash
cp docs/wiki/*.md ../tariffy.wiki/
cp -r docs/wiki/images ../tariffy.wiki/
```

The images point to `https://raw.githubusercontent.com/wiki/weskona/tariffy/images/<file>`, exactly the place where they lie after copying. That is why the paths in the wiki repository must be `images/<file>`.

## Report a bug

Use the form "Bug Report" under [Issues](https://github.com/weskona/tariffy/issues/new/choose) and give:

1. the **version** of Tariffy and of Home Assistant
2. the **log** filtered for `tariffy`, best with debug level (see [Troubleshooting](EN-Troubleshooting#enable-the-debug-log))
3. the **steps** to reproduce the problem

Remove personal data such as customer number, meter number and market location ID. The diagnostics ([Troubleshooting](EN-Troubleshooting#download-diagnostics)) already redact them. The issue forms are checked by `tests/test_issue_templates.py`.
